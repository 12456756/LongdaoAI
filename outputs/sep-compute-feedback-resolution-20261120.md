# SEP v1 联调反馈处理结果

日期：2026-11-20。对应 SEP 提供的 `sep-compute-api-v1-feedback-2026-11-20.md` 和 `sep-compute-v1-review-and-local-integration-2026-11-20.md`。

## 两项代码修复

1. 企业 `GET /v1/models` 使用单独的严格目录逻辑。仍需用途 Key、服务签名和企业编号，不需要执行编号。按现有分组、白名单/映射、分组显式列表、渠道限制、上游端点能力和基础价格收敛，并按 Key 用途返回模型；无默认目录兜底。空目录返回 `data:[]`，依赖故障返回错误，不把降级结果当完整权限集合。超过 2000 条明确报错，没有静默截断。普通 Key 目录协议保留。
2. 控制接口、SEP 网关鉴权和目录错误统一附带 `request_id`，与 `X-Request-ID` 一致。保留已有业务错误 code/message/status，分类超时、中断、数据库、依赖网络和未分类错误；底层错误增加脱敏 diagnostic，并按同一请求编号记日志。数据库只公开 SQLSTATE，不公开 SQL、行内容或连接凭证。

代码：`backend/internal/service/sep_models.go`、`sep_errors.go`，`backend/internal/server/middleware/sep_errors.go`，`backend/internal/handler/gateway_handler.go`、`sep_handler.go`。

## 既有方式确认

- 管理员校验继续使用管理员算力账号的普通模型 Key，经原模型目录和图片/视频 pricing 接口。旧 USD 报价仅用于配置校验，不生成、不扣生成费；管理员 Key 不是登录 token 或管理 API Key。
- 企业媒体 Key + 服务签名取得 CNY 企业报价和 quote_id。管理员报价不参与企业真实扣费。
- 原新增 validation pricing 作为可选路径保留，SEP 本批不需要改用它。
- SEP 维护规格及企业可选范围；算力平台维护价格、倍率、统一汇率与实际人民币费用。
- 原开户、免费/付费拆分、幂等资金划转、固定水位流水及三 Key 共用余额规则保留。

上述约定及 N01 原快照恢复、N05 回执实际字段、JSON 整数账号 ID 范围和服务单公钥切换规则，已补入 `docs/development/sep-compute-platform-api-v1.md`。

## 本地配置与验证

已验证交付文件只含两份公钥及版本：Ed25519 签名公钥、3072 位 RSA 加密公钥。已通过本地管理员配置接口导入 `public-configuration.json` 的公钥，未读取私钥，集成保持关闭。此套仅供本地开发，生产需另行生成。

本地算力后端仍为 `http://127.0.0.1:28080`，管理前端为 `http://127.0.0.1:3301/admin/sep`。跨机器访问仍需配置可达的 HTTPS 地址。正式测试分组与管理员校验 Key 使用双方确认的配置，不以本次脚本的临时夹具充当正式凭证。

后端 SEP、普通模型目录、媒体计费、鉴权、基础价格、汇率及支付定向回归通过，服务构建通过。新增测试覆盖混合分组用途、Token 图片别名、空目录、资源撤回、基础价格缺失、端点能力限制、2000 条上限，以及错误分类/脱敏/追踪编号。

本地真实 HTTP + PostgreSQL 回归新增：三个分组均含混合用途资源时仍分别返回相应模型；空分组不回退；撤销白名单后立即消失；错误正文 request_id 与响应头一致。原开户/JWE、零余额全免费、混合结算、幂等划转、固定快照、报价、异步费用和断连不补生成全部继续通过，供应商均为本地模拟，未产生真实费用。

这是算力平台对反馈的修复及本地回归结果。SEP 报告中的 71/473 项是 SEP 自身已报告的验证，不计为本次算力平台重新执行的测试。尚未把双方真实用户入口、免费权益和钱包资金流程全部切换，不据此宣称整体方案完成或可上线。未提交、合并或部署生产。
