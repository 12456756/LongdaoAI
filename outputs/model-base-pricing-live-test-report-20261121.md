## 6. 未通过：视频正常生成

复现输入：

```json
{
  "model": "seedance-2.0",
  "prompt": "A red toy car moves slowly across a white table. Static camera, simple scene.",
  "seconds": "4",
  "resolution": "480p",
  "size": "854x480"
}
```

1. 使用视频测试 Key 调用 `POST /v1/sub2api/videos/pricing`，传 model、operation=text-to-video、resolution=480p、duration_seconds=4。
2. 报价返回 200，amount_usd=1.4784000000，同时返回 pricing_version。
3. 在 `POST /v1/videos` 中同时携带 `X-Video-Operation: text-to-video` 和报价的 `X-Video-Pricing-Version`。
4. 本地报价版本检查通过后，收到上游 HTTP 400：`X-Video-Operation must be text-to-video or image-to-video`。

证据：

- 客户端请求编号：`ab9606b0-c662-4d0b-b7ce-5fd1c694a003`。
- ops_error_logs ID 107：error_source=upstream_http，upstream_status_code=400。
- 该请求没有成功返回视频任务 ID，没有视频用量记录，没有本地视频扣费。
- 对该失败请求查询视频费用返回 pending 和空金额；这里表示未找到已结算证据，不表示任务已被接收。
- 当前账号使用 openai_videos 协议。代码 `backend/internal/service/openai_videos.go` 的 ForwardVideo 在构建上游请求时只设置认证、Accept、Content-Type、Idempotency-Key 等头，没有转发 X-Video-Operation。
- 由于当前上游要求操作类型，该头在转发路径中的缺失与错误吻合。还需核对上游自己的报价版本协议；不能将本地 Key 绑定的报价版本直接当作上游 Key 的报价版本。

建议先修复或明确当前账号视频协议的转发约定，再重跑 4 秒、480p 的提交、轮询、下载、扣费和重复查询。目前无法验证视频文件实际时长和像素尺寸，也无法验证真实成功视频扣费是否与报价一致。本次没有修改转发业务代码或通过改动共享账号配置绕过错误。
