## 已实现

1. 企业开户在一个数据库事务中创建专用账号和 chat/image/video 三个 Key。同企业、同开户编号并发重放不重复创建；不用管理员密码，不按邮箱合并。
2. 管理员页面 `/admin/sep` 配置三个开户默认分组、Ed25519 签名公钥和 RSA 凭证加密公钥。企业详情可调整各 Key 分组、停用企业，查看六位小数 CNY 余额、最近 100 笔执行费用及分页流水。企业列表当前最多 200 家。
3. N01/N02/N04-N09 八个服务接口及平台媒体参数校验接口；原模型入口增加企业、执行编号、报价和服务签名校验，复用原 JSON/SSE、图片和视频协议。
4. 专用 `sep_settlement_v1` 只确认实际费，跳过原 USD 余额和用户/Key 全额扣款。SEP 提交最终免费/付费拆分后，事务内只扣付费部分；保留原上游账号用量统计。
5. 资金划转与结算使用数据库行锁、业务编号唯一约束及持久化回执。重复决定只入账一次，退回余额不足不会透支；被拒划转为终态，重放不因后来充值而变成功。
6. CNY 资金使用 NUMERIC(24,6)，API 用固定六位小数字符串。金额从既有美元费用计算后，按冻结的统一汇率转 CNY；资金划转直接增减 CNY。已有企业 CNY 余额不会随汇率变化重算。
7. 执行前固化基础价格、汇率及倍率，派发前原子标记一次执行权；内部切换账号、HTTP 重试和重定向不能造成第二次生成。结果不明时返回待确认费用，不自动归零或补生成。
8. 图片/视频企业报价返回真实 CNY 值及一分钟报价编号，执行核对规格和归属。视频受理阶段保持 pending，原状态查询或 N04 查询取得完成证据后确认实际费用。
9. Ed25519 服务签名覆盖请求内容、路径和关键 Header；nonce 持久化防重放。JWE 使用 RSA-OAEP-256/A256GCM，至少 3072 位 RSA。SEP 私钥不进入平台配置。企业 Key 的管理员列表响应脱敏。
10. 独立平台校验身份只做图片/视频规格报价；不能作为企业可执行报价或最终结算金额。企业账户的普通充值、任意调 USD 余额、登录身份修改及普通 Key 操作受到服务层和数据库保护。

- 签名篡改、nonce 重放、用途和企业不匹配被拒绝。零余额对话、全免费结算、多进程等价并发结算、执行去重均符合预期。
- 缓存读取 Token 按基础价格计费；修改执行中的汇率和倍率，最终费用仍使用原快照。

## 当前边界

- 企业 Key 轮换 N03 按交接文档延期；签名配置只有一个活动版本，换公钥需协调切换。
- SEP 业务代码尚未修改，仍需对接开户、解密存储、请求签名、免费/付费拆分、本地账务事务、可靠重试及对账。
- 平台使用标准计费运行模式。媒体报价复用现有 OpenAI 分组能力；无法在执行前确定金额的 Token 媒体模型返回不可报价，不虚构零元或预占金额。
- 没有新增平台远端冻结资金，当前 frozen 为零；媒体预占仍在 SEP。没有任意调账或删除账务 API。
- 未决视频按 N04/原状态查询推进，没有额外后台轮询器；失败、取消和缺失费用证据保持 reconciling，需要后续核对，不自动免费。
- Key、分组或上游账号被删除后的恢复不在本轮保障范围；停用企业仍可结算和查询。整个集成关闭会拒绝所有服务请求。
- API Key 静态存储沿用原平台，不能将 JWE 交付加密等同于数据库全量加密。
- 未部署生产、未与实际 SEP 系统完成跨系统验收。联调前须由 SEP 提供真实公钥、管理员选择正式测试分组后启用。
