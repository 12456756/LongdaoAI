# 算力平台模型基础价格管理开发方案

日期：2026-11-20。项目：LongdaoAI。状态：已在本工作树实施并完成隔离环境验证，未合并、未上线。

本文依据当前工作树代码和本次讨论整理；未读取生产数据库，不代表线上已完成配置或具备下述能力。

实施细节、验证结果和本地预览见同目录 `model-base-pricing-implementation-20261120.md`。

## 1. 目标与已确认范围

用管理员维护的模型基础价格体系，替换目前代码内置、JSON 文件和远程同步的默认模型价格体系。

已确认的业务操作如下：

1. 管理员添加或编辑上游账号时，选择账号所属的上游公司，并在模型限制所选模型下配置上游原价、上游折扣、公司加价倍数。一家上游公司可以有多个账号，分别配置不同模型厂商的模型。
2. 系统为每个账号、每个模型计算候选基础价格。
3. 单独增加“模型基础价格”页面，列出当前平台支持的模型；建议列按上游公司分组，组内按不同账号展示候选价格。
4. 管理员为每个模型选择一个账号的整套候选价格，作为该模型统一基础价格。
5. 计费时使用选定基础价格，后续用量计算及现有倍率逻辑继续执行。

核心约束：

- 用户倍率就是现有分组相关倍率，不新增用户倍率字段。
- 同一模型的统一基础价格不随实际调度账号改变；不同分组仍可通过现有倍率形成不同最终售价。
- 选择价格来源不等于指定模型调用账号，不改变现有调度规则。
- 新体系是替换旧价格来源，不是增加一个优先级后继续使用旧价格兜底。
- 未设置基础价的模型显示“未定价”，不自动套用其他模型或通用默认价格。
- 不新增采购成本、毛利核算系统，不重构现有账号统计和额度口径。

## 2. 价格定义及计算

### 2.1 账号候选基础价

对账号中一个模型的每个计费项分别计算：

```text
候选基础单价 = 上游原始单价 × 上游折扣系数 × 公司加价倍数
```

例如：五折填写 `0.5`，不打折填写 `1`；公司加价两倍填写 `2`。

折扣系数和公司加价倍数在同一账号、同一模型下统一应用于该模型的各项原价。第一版不增加每个计费项各自的折扣配置。

### 2.2 模型统一基础价

管理员从候选账号中选择一套价格；输入、输出、缓存及规格档位整体选取，第一版不支持从多个账号分别拼接。

```text
模型统一基础价 = 管理员选中账号的整套候选基础价
```

例如，账号 A 的图片候选价是 `0.10 USD/张`，账号 B 是 `0.08 USD/张`，管理员选择 B，则实际调用 A 或 B 时均以 `0.08 USD/张` 作为倍率前单价。

### 2.3 与现有收费的衔接

```text
倍率前费用 = 按实际用量、计费方式和规格，使用选定基础价计算
实际用户费用 = 倍率前费用 × 现有生效倍率
```

现有分组倍率、用户专属倍率、高峰倍率、图片和视频独立倍率，以及批量任务的折扣、冻结比例等计算规则不在本次改动中重新定义，也不在候选基础价中预先乘入。

公司加价只在生成候选基础价时乘一次，运行时不能再次叠加。

## 3. 价格明细

| 类别 | 原价配置项 | 后台显示单位 |
|---|---|---|
| Token | 普通输入、普通输出、缓存读取、缓存写入 | USD/百万 Token |
| Token 扩展 | 图片输入 Token、图片输出 Token | USD/百万 Token |
| 缓存写入细分 | 5 分钟、1 小时缓存写入价，按模型能力提供 | USD/百万 Token |
| 图片按张 | 与现有生图能力对应的尺寸、必要质量档位 | USD/张 |
| 视频按秒 | 与现有视频能力对应的分辨率等规格 | USD/秒 |
| 已有按次能力 | 明确按次或按条的模型价格，不与每秒价混用 | USD/次或 USD/条 |

基础价格配置必须带计费方式、单位和规格，不能只保存一个没有单位的金额。图片模型是否按 Token 计费由模型的明确价格配置决定，不再依靠是否命中渠道价格来判断。

现有 Priority/Flex、长上下文档位等计算能力继续保留。原先从旧价格数据中读取的专用单价、阈值或策略元数据，迁入新价格配置所需的扩展字段；本次不重新设计这些规则。价格明细和预览必须能解释实际使用的单价，不能保留隐藏的硬编码单价兜底。

### 3.1 缓存计费现状

当前已经将缓存费用计入总费用，不需要重新实现缓存计费核心：

```text
Token 倍率前费用 =
  普通输入数量 × 普通输入基础价
+ 普通输出数量 × 普通输出基础价
+ 缓存读取数量 × 缓存读取基础价
+ 缓存写入数量 × 对应缓存写入基础价
+ 适用的图片 Token 等费用
```

`billing_service.go` 中的 `computeTokenBreakdown` 会累加 `CacheCreationCost` 和 `CacheReadCost`；`computeCacheCreationCost` 支持标准写入价以及 5 分钟、1 小时细分价。

OpenAI 路径会从输入总量中减去缓存读写数量，避免重复按普通输入计费；Anthropic 路径使用其已经分开的用量字段。继续复用各协议当前的用量归一化，不能跨协议统一减一次缓存数量。

### 3.2 空值与零值

- `null` 表示未设置；`0` 表示管理员明确设置免费，两者必须区分。
- 按模型能力声明计费项是否适用；适用且必需的字段未设置时，不允许保存为可用基础价。
- 不适用的缓存项不强制填写；不能把“上游没有返回缓存用量”解释为已有缓存免费。
- 单价、折扣和倍数使用十进制精度校验，拒绝负数、非有限值和单位不匹配。
- 建议折扣范围为 `0` 至 `1`，公司加价倍数为非负数，默认均为 `1`；免费配置应在保存预览中明确显示。

## 4. 管理页面

### 4.0 上游公司与账号归属

账号管理新增“所属上游公司”字段，以独立的上游公司记录关联账号，不通过账号名称或 API 地址推断归属。管理员可选择已有公司或新建公司，第一版公司信息只需名称和备注；支持修改。已有账号由管理员补充归属，迁移前显示“未归属”，不自动猜测。

三层含义分别为：上游公司是采购服务提供方，例如脑生云；账号是该公司下的一份调用配置；模型厂商是模型的开发方，例如 OpenAI、Anthropic。现有协议平台字段继续表示接口或调度平台，不作为上游公司字段复用。

```text
脑生云（上游公司）
  -> 账号 A：配置 OpenAI 模型
  -> 账号 B：配置 Anthropic 模型
  -> 账号 C：配置图片或视频模型
```

账号列表显示所属上游公司，并提供公司筛选。价格仍配置在具体账号、具体模型上，不因账号属于同一家公司就共用折扣、加价倍数或模型限制。修改归属本身不改变已有价格和已选基础价。

### 4.1 添加及编辑账号

账号基本信息增加“所属上游公司”选择；在模型限制区域之后增加“模型原价与公司加价”配置，创建、编辑使用同一个价格表单组件。

每个已选模型显示：模型名称、实际上游模型名、计费方式、上游原价明细、采购折扣、公司加价倍数、自动计算的候选基础价。

账号模型限制、模型映射继续使用现有能力。白名单新增模型时增加价格行；取消选择时保留或明确处理已保存价格，不因表单切换静默丢失。映射模式同时展示对外模型与上游模型，避免把上游采购对象和对外定价对象混淆。

空白名单、通配符或透传账号无法穷举全部模型时，允许从同步发现结果或手动输入的明确模型中配置价格；通配符本身不能成为模糊价格匹配规则。

保存账号和模型价格应保持一致性，失败时不能出现“账号已创建但价格悄悄丢失”的状态。账号创建后仍可编辑价格，不要求重新创建账号。

### 4.2 模型基础价格页面

建议路由：`/admin/model-pricing`，入口放在系统设置下的“模型基础价格”独立页面，不依赖渠道定价。列表示意：

| 模型 | 计费方式/规格 | 脑生云 / 账号 A | 脑生云 / 账号 B | 其他上游 / 账号 C | 当前基础价来源 | 状态 |
|---|---|---|---|---|---|---|
| 模型 X | 图片 1K，USD/张 | 0.10 | 不支持 | 0.08 | 其他上游 / 账号 C | 已设置 |
| 模型 Y | 视频 720p，USD/秒 | 不支持 | 0.15 | 未配置 | 未选择 | 未定价 |
| 模型 Z | Token，USD/百万 Token | 展开明细 | 不支持 | 展开明细 | 脑生云 / 账号 A | 已设置 |

建议实际界面采用两级表头：一级是上游公司，二级是该公司下的账号；上述 Markdown 用“公司 / 账号”表示。页面支持按模型搜索、按上游公司/平台/计费类型/定价状态筛选。模型及当前基础价列固定；账号列横向滚动，并可筛选展示账号，避免账号较多时无法比较。

一家公司的多个账号如果支持同一模型且价格不同，应保留各自候选价，不自动取最低、最高或平均值。基础价选择仍定位到具体账号价格，当前来源同时显示公司和账号，避免只选公司后无法确定使用哪套价格。

选择操作以单选方式完成，同一模型只选一个来源账号。保存前展示选中整套基础价；保存后显示来源账号和价格版本。不能只比较 Token 输入价，却忽略输出或缓存价格差异。

“全部支持模型”的目录来自账号模型限制、映射和已有模型发现结果的去重汇总，不从旧价格表反推。手动配置的自定义模型也需要进入目录；账号无价格时仍显示该模型及未配置状态。

### 4.3 来源价格变更

建议第一版保存选中价格的快照。后续账号原价、折扣或公司加价改变时，页面提示“来源价格已变化”，由管理员更新基础价；不会因一次账号编辑悄悄改变收费。

本次按此方式实现：修改账号价格不会自动修改模型基础价，需在基础价格页面重新确认更新。

源账号停用或删除时，已保存的价格快照继续可解释并标记来源状态；实际调用是否可用仍按现有账号调度判断，不自动切换到其他账号价格。

## 5. 数据及接口设计

### 5.1 数据结构

新增独立业务表，不将价格塞进账号凭据。以下为建议名称，实施时按仓库规范命名。

| 数据对象 | 主要字段 | 约束 |
|---|---|---|
| `upstream_companies` | 公司 ID、名称、备注、创建及修改时间 | 一个公司可关联多个账号；有关联账号时不直接删除 |
| `accounts.upstream_company_id` | 所属上游公司 ID | 单个账号只归属一个公司；存量账号暂允许未归属 |
| `account_model_prices` | 账号 ID、定价模型标识、上游模型名、计费方式、原价明细、折扣、公司加价倍数、修订号 | 同一账号、模型及必要计费配置唯一 |
| `model_base_prices` | 模型标识、来源账号价格 ID、来源修订号、选定价格快照、基础价版本、修改人和时间 | 同一对外模型只有一套当前基础价格 |
| 基础价修改记录 | 修改前后快照、操作人、时间 | 可追溯历史修改，不覆盖旧请求使用的版本 |

建议以价格项目和规格列表保存整套明细，统一表达 `text_input`、`text_output`、`cache_read`、`cache_write`、`image_input`、`image_output`、`image`、`video` 等计费项；使用结构化解析和校验，不能依靠前端自由文本。

模型标识以稳定的对外模型身份为准，必要时包含协议平台维度；同一 OpenAI 兼容对外模型在不同供应商账号下仍能并列比较。只支持明确模型名和已声明的别名关系，不保留“未知型号套用同系列价格”的行为。实际路由到不同上游模型时，用户基础价仍按对外模型标识读取。

Token 后台继续以 USD/百万 Token 显示；接口和数据库固定单位并明确字段含义。原价及乘法使用数据库 `NUMERIC` 和明确的十进制处理，运行时适配现有计算结构时只转换一次，统一舍入边界。

### 5.2 管理接口

| 接口建议 | 功能 |
|---|---|
| 上游公司管理接口 `/api/v1/admin/upstream-companies` | 查询、新建和修改公司，供账号归属选择和页面分组使用 |
| 账号创建/更新接口增加 `upstream_company_id`、`model_prices` | 与账号一并保存公司归属、模型原价和系数 |
| `GET /api/v1/admin/accounts/:id/model-prices` | 读取账号模型价格明细 |
| `GET /api/v1/admin/model-pricing` | 分页查询模型、当前基础价和各账号候选价格 |
| `PUT /api/v1/admin/model-pricing/base-price` | 指定模型、来源价格 ID 和来源修订号，保存基础价快照 |
| `GET /api/v1/admin/model-pricing/history` | 查询模型基础价修改记录 |

保存时后端重新计算候选价格，不能直接信任前端传来的最终金额。修订号不匹配时返回冲突，刷新比较结果后重新保存。接口使用现有管理员权限和响应格式。

### 5.3 运行时价格服务

新增数据库支持的统一基础价读取服务，输出计费方式、各项单价、规格和版本。所有报价与计费入口使用这一个服务，现有 `ModelPricing`、`UsageTokens`、`CostBreakdown` 可继续作为计算适配结构。

读库失败与模型未定价必须区分；不能把数据库故障转换成免费或未配置。缓存按模型和基础价版本管理，更新后失效；报价校验及请求使用的快照必须与保存版本一致。

## 6. 接入现有项目

### 6.1 替换价格来源

运行时新链路为：

```text
明确的模型身份及计费规格
  -> 数据库中的管理员选定基础价格
  -> 现有用量与计费计算
  -> 现有倍率处理
  -> 现有扣费、额度和用量记录
```

以下旧价格来源退出模型收费路径：

- `BillingService.initFallbackPricing`、`getFallbackPricing` 中的内置模型单价。
- `PricingService` 远程/本地 JSON 单价、模型系列模糊匹配及跨模型回退。
- 图片通用默认价、Grok 图片和视频内置价格。
- 渠道和分组中的旧模型基础单价覆盖路径，避免覆盖管理员选定基础价；现有渠道模型映射、限制和分组倍率继续保留。

旧 JSON 中的上下文窗口、模型能力等非价格数据如果仍被模型发现使用，可按用途保留；它们不能再成为收费单价来源。旧代码和数据可以用于一次性迁移参考，不能作为运行时兜底。

分组页面旧图片/视频单价输入及前端硬编码默认价格预览需要同步退出新定价入口，倍率控件保持原样。渠道定价不作为本功能的操作前提，不要求管理员先配置渠道。

### 6.3 请求时序及缺价行为

在调用上游之前校验当前模型及已知规格的基础价，保存价格版本和本次所需的快照。流式或异步记账不能在结束时重新读取一份管理员刚修改的价格。

文本无法提前确定最终 Token 数量，但可以提前确认可用单价，结束后按实际用量结算。图片、视频按其明确计费单位及实际可计费用量计算，不改变生成成功、任务受理和计费时点的既有规则。

未定价或必需规格缺价时明确返回价格不可用，且尚未派发上游。图片、视频报价仍可沿用现有 `unavailable` 形态，不能报 `0`；运行时异常不能走现有“缺价记录零费用”分支冒充正常结算。

已提交任务继续使用其价格快照。历史无快照任务在切换前单独清理或确认结算方案，不能用新的基础价重算已有任务。

## 7. 与业务平台联调

继续使用现有 Token 倍率查询、图片/视频报价和单请求账务查询接口；内部价格来源切换后保持既有字段含义。

- `/v1/sub2api/billing` 仍只表示现有 Token 倍率，不把上游折扣或公司加价混入倍率。
- 图片、视频报价从新基础价计算；返回金额已包含对应现有倍率，业务平台不能重复乘。
- 价格版本应包含或关联新基础价版本；视频现有报价保护继续使用同一版本校验。
- 最终费用仍以单请求账务接口确认的实际扣费为准，不能凭报价假定已扣费。
- 如业务平台需要同步 Token 单价，增加按当前 Key 可用模型查询的价格接口，返回输入、输出、缓存等单价、单位和版本；这是独立于倍率接口的契约扩展，不要求本次修改业务平台代码。
- 非管理员接口不返回上游原价、采购折扣和公司加价等内部配置。

## 8. 数据准备与切换

1. 盘点当前可调用模型、账号模型映射、计费方式和必要规格，补充账号的上游公司归属，不以默认价格文件代替真实支持模型列表。
2. 完成账号价格和基础价页面，先由管理员填写并选择各模型基础价。
3. 旧价格可作为一次性导入参考，但上游折扣及公司加价必须由管理员核实，不能从现有账号倍率反推。
4. 切换前输出未定价模型、缺失规格和在途任务清单，完成所需价格配置及旧任务处理。
5. 一次性切换模型收费价格来源，同步失效价格缓存，检查报价与实际扣费一致。
6. 切换后新请求不回退旧价格体系；历史用量和账单保持原金额，不重新计算。

临时开发验证可以在独立环境比对旧、新计算结果；不能将生产长期同时使用两套价格或隐式回退作为最终实现。

## 9. 开发顺序

| 阶段 | 交付内容 |
|---|---|
| 1. 数据及计算 | 公司与账号归属、价格表结构、十进制候选价格计算、单位和规格校验、统一基础价服务 |
| 2. 账号配置 | 公司选择与维护、创建/编辑账号的模型原价、折扣、公司加价设置及完整保存 |
| 3. 基础价页面 | 模型目录、按公司分组的账号价格对比、整套价格选择、版本和历史 |
| 4. 计费接入 | 普通及流式网关、图片、视频、批量任务接入；旧单价来源退出 |
| 5. 联调与切换 | 报价一致性、缺价处理、数据检查、现有倍率回归和文档更新 |

## 10. 验证与验收

- 同一上游公司可以关联多个账号，创建、编辑和账号列表正确显示归属；上游公司不与协议平台或模型厂商混用。
- 基础价页面按公司分组展示账号，同公司下同模型的不同账号价格仍可分别选择，来源记录精确到账号价格。
- 两个账号的同一模型分别配置不同原价/折扣/加价，候选价计算正确，编辑后能够完整回显。
- 模型基础价页面列出已配置及未配置价格的支持模型，管理员能比较并选择一个账号的整套价格。
- 选择 B 的价格后，实际调用 A、B 均使用同一基础价；分组倍率只按现有流程应用一次。
- 输入、输出、缓存读取、缓存写入及适用的 5 分钟/1 小时明细正确参与计算，普通输入不与缓存重复计费。
- 图片尺寸、视频分辨率、按秒和按次单位正确；Token 模式图片仍按其完整 Token 价目计算。
- 分组/专属/高峰/独立倍率，以及批量折扣和冻结流程的已有测试继续通过，本次不改变这些规则。
- 明确免费价格 `0` 与未配置 `null` 行为不同；未知模型不会套用其他模型或通用价格。
- 上游调用前完成基础价检查，缺价不会产生上游生成请求；数据库故障不会被当成免费。
- 普通、流式、协议转换、异步图片、视频及批量图片均使用新来源，不能只验证单一 API。
- 报价与实际收费使用同一基础价版本，管理员改价不影响已经锁定价格的请求。
- 基础价并发修改、缓存失效、来源账号修改或删除均有明确行为，历史账单仍可追溯。
- 检查旧价格服务全部调用点，证明正式收费路径不再依赖代码单价、远程单价或旧渠道/分组单价覆盖。
- 后端运行对应计费、缓存、报价和批量结算测试；前端运行表单/页面验证、类型检查，并检查桌面及窄屏横向价格表。

## 11. 实施前落实的细节

以下事项不改变上述业务范围，属于具体实现约定：

1. 基础价来源修改后采用“提示差异、手动更新快照”的建议方式，还是自动更新；本文按前者设计。
2. 明确第一批启用的模型和各计费方式，完成必要缓存、规格及既有扩展价目的数据准备。
3. 确认从哪个配置入口移除旧单价输入，以及已有在途无快照任务的切换安排。

最终验收目标：管理员完成账号模型价格配置和基础价选择后，平台仅使用所选基础价格替代旧默认价格体系；其后的实际用量计算及既有倍率规则保持原有行为。
